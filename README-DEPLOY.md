# BORSH VPN BOT — готовый код для хостинга (bothost)

Файл `vpn-1.py` уже содержит рабочий токен бота **@vpnborsh_bot**, ссылку подписки,
реквизиты карты и ID админа. То есть заливается и запускается без настройки переменных:
`python vpn-1.py` — и всё.

Переменные окружения нужны только если захотите что-то переопределить, не трогая код.

## Установка на bothost

1. Загрузите `vpn-1.py` и `requirements.txt` в контейнер (файловый менеджер панели или
   `git clone` в веб-терминале).
2. Стартовая команда:

```
pip install -r requirements.txt && python vpn-1.py
```

Если панель ставит зависимости сама из `requirements.txt` — достаточно `python vpn-1.py`.

3. Запустите контейнер и смотрите лог. Успешный старт:

```
[✓] Middleware (бан + антиспам) подключён
[✓] Бот: @vpnborsh_bot
```

## ВАЖНО: сначала остановите старый запуск

Этот токен **уже кем-то опрашивается прямо сейчас** — при запуске код получает:

```
409 Conflict: terminated by other getUpdates request;
make sure that only one bot instance is running.
```

Значит, с этим токеном работает ещё одна копия бота: старый контейнер в панели, копия на
ПК/телефоне или чужая копия (токен лежал в публичном репозитории). Telegram разрешает
только один `getUpdates` на токен, поэтому новый контейнер будет молчать.

Что сделать:
1. Остановите старый контейнер в панели bothost (кнопка «Остановить»), все локальные
   копии — тоже.
2. Если подозреваете, что копия не ваша: `@BotFather` → `/mybots` → бот → **API Token** →
   **Revoke current token**, новый токен вписать в `_DEFAULT_BOT_TOKEN` в начале файла.
3. Запустите контейнер снова. В логе должно быть `[✓] Бот: @vpnborsh_bot` и дальше тишина
   без `409`.

## Данные и перезапуски

БД, картинки и lock-файл лежат в `DATA_DIR`:

- в контейнере bothost — `/app/data` (по умолчанию в коде, сохраняется между перезапусками);
- локально (нет папки `/app`) — рядом со скриптом.

Старую базу `borsh_vpn.db`, если она есть, положите в `/app/data/`, иначе пользователи,
балансы и платежи начнутся с нуля:

```
mkdir -p /app/data && cp borsh_vpn.db /app/data/
```

Схема обновляется сама при старте — миграции рассчитаны на базу версии 3.0.

## Переопределение через окружение (необязательно)

| Переменная | Что задаёт | Значение по умолчанию |
|---|---|---|
| `BOT_TOKEN` | токен бота | вписан в коде |
| `DATA_DIR` | папка данных | `/app/data` (или папка скрипта) |
| `ADMIN_IDS` | ID админов через запятую | `8174421672` |
| `MASTER_SUB_URL` | ссылка подписки для клиентов | вписана в коде |
| `CARD_NUMBER`, `CARD_HOLDER` | реквизиты пополнения | вписаны в коде |
| `SUPPORT`, `DEV` | контакты | `@fuckrizer` |
| `TRIAL_URL`, `PRIVACY_URL`, `TERMS_URL` | сайт и юр. ссылки | borshvpn.com / telegra.ph |

## Что исправлено по сравнению с версией из репозитория

| Было | Стало |
|---|---|
| БД рядом со скриптом — терялась при перезапуске контейнера | `DATA_DIR` (`/app/data`), БД и картинки переживают рестарт |
| Пробный период обнулял оплаченный срок (300 дней → 5) | оплаченный срок не сокращается |
| Двойной клик по «Активировать пробу» | атомарный `claim_trial()`, 5 дней один раз |
| Lock-файл рядом со скриптом | в `DATA_DIR` |
| Нет зависимостей и `.gitignore` | `requirements.txt`, `.gitignore`, `Dockerfile`, `.env.example` |

Проверено локально: `py_compile` проходит; на тестовой базе оплаченный срок сохраняется,
второй `claim_trial` возвращает `False`, свежий триал = 5 дней, повторный `confirm_payment`
не начисляет деньги дважды. Реальный старт с этим токеном доходит до `[✓] Бот: @vpnborsh_bot`.

## Частые проблемы

**`409 Conflict`** — см. раздел выше: остановите все прочие копии или перевыпустите токен.

**`database is locked`** — два процесса пишут в один файл; запускайте один контейнер.

**Бот молчит, процесс `running`** — смотрите лог: чаще всего 409 либо неверный токен.

**Нет фото приветствия** — положите картинку в `/app/data/image/` (jpg/png/webp).

## Про публикацию кода

Пока токен и ссылка подписки вписаны в файл, его нельзя выкладывать в открытый
репозиторий: любой, кто увидит токен, сможет читать переписку бота, подтверждать себе
платежи и делать рассылки, а ссылка подписки даёт бесплатный VPN. Для публичного репозитория
оставьте в коде пустые значения и задайте всё через переменные окружения.

## Бизнес-логика (не баг, но влияет на деньги)

Бот выдаёт **одну и ту же** ссылку подписки всем — и платящим, и пробным. Один перепост
ключа открывает бесплатный VPN всем, а новый Telegram-аккаунт каждые 5 дней даёт
бесконечный триал. Если нужен реальный paywall, ключи надо выпускать персонально через
API панели VPN.
